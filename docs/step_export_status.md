# STEP export — status

Branch: `feature/step-export`

## Goal

Add STEP as pCAD's 3D CAD interchange format while leaving existing STL and DXF behavior unchanged. STEP should preserve native B-Rep/analytic geometry where the converter supports it and warn when a construct requires mesh fallback.

## Current state

### Step 1 — Product/API vertical slice: complete

- [x] Add `.STEP` to the existing export menu as `3D CAD Exchange`.
- [x] Keep STL and DXF paths unchanged.
- [x] Add authenticated `POST /api/export/step`.
- [x] Add browser STEP service and `.step` download helper.
- [x] Pin the provider contract to `scad123d 0.5.0`.
- [x] Surface provider mesh/fallback warnings to the UI.
- [x] Keep STEP generation lazy/on-click so normal editing and preview pay no B-Rep cost.

### Step 2 — Native-converter sandbox: implementation complete, live gate pending

- [x] Add a dedicated rootless-Podman runner.

- [x] Read-only container root filesystem.
- [x] `no-new-privileges` and `cap-drop=all`.
- [x] PID, memory, CPU and runtime limits.
- [x] Only one SCAD input file is mounted read-only.
- [x] Only the dedicated temporary output directory is mounted read-write.
- [x] Keep Podman cidfile outside sandbox-visible paths.

## Validation evidence so far

Completed in the implementation environment:

- `bash -n` passes for the sandbox runner, image-build helper and smoke-test script.
- New STEP server/test TypeScript sources parse successfully with the TypeScript compiler API.
- OpenSCAD upstream commit/date and its Qt6/headless Linux CI path were verified before changing the provider image.
- Branch comparison is based on the requested master and remains 0 commits behind it.

Observed on the real pCAD host before the source-build refactor:

- the initial AppImage-based provider image reached OpenSCAD startup but failed because the minimal Ubuntu image lacked `libharfbuzz.so.0`;
- this exposed that AppImage host-runtime assumptions were the wrong packaging boundary for the sandbox;
- the AppImage approach was replaced rather than continuing to add host-style desktop libraries manually.

Not claimed yet for the new source-based image:

- `npm test`
- `npm run typecheck`
- `npm run lint`
- `npm run build`
- successful Podman source image build
- real scad123d/OpenSCAD conversion

The execution environment used for the GitHub implementation does not provide the user's rootless Podman runtime, so the source image and conversion gates require the real pCAD host before Step 2 can be marked externally verified.


Expected final line:


Then keep `PCAD_STEP_EXPORT_RUNNER` exported in the shell that starts pCAD and run the normal app.

## Step 3 — Representative model compatibility gate: next after smoke test

Test at minimum:

- primitive cube;
- cylinder/sphere and curved surfaces;
- boolean hole/difference;
- union/intersection;
- `linear_extrude`;
- `rotate_extrude`;
- `hull`;
- `minkowski`;
- BOSL model;
- BOSL2 model;
- MCAD model;
- imported single-file SCAD;
- colored/multi-body model;
- an intentionally unsupported construct that triggers mesh fallback.

For successful models verify:

- dimensions/units;
- holes and topology;
- number of solids/bodies;
- analytic curved surfaces where expected;
- absence of unintended tessellation;
- useful fallback warning when exact B-Rep is impossible.

Initial receiving-CAD gate: FreeCAD and/or Rhino. Follow with AutoCAD and MicroStation when available.

## Known boundary

STEP V1 currently sends only the complete SCAD source into the sandbox. Custom relative project files and `import()` mesh/assets are not transferred. Do not widen the sandbox to arbitrary host paths to support these; multi-file/asset support needs an explicit normalized workspace input design.
