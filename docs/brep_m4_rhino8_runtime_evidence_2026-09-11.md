## Rhino 8 host-save normalization finding

The first strict returned-GHX validation exposed a real Rhino 8 persistence normalization:

```text
missing_rhinocode_library
script_library_changed
```

Inspection showed that Rhino 8 may omit the generated `Lib` item on the Python 3 Script object and omit the explicit RhinoCodePluginGH entry from `GHALibraries` when re-saving a valid built-in Python 3 Script definition.

This is host serialization normalization, not a canonical model mutation. The validator was corrected narrowly:

- `generated` mode still requires explicit RhinoCodePluginGH `Lib` identity and library declaration;
- `returned` mode accepts the host-normalized omission only when the Python 3 component identity itself is still the exact supported built-in component;
- an explicitly present foreign `Lib` GUID remains rejected;
- the Grasshopper host envelope must still contain a valid `GHALibraries` section;
- Python source, script component GUID and instance GUID, inputs, outputs, wiring, type hints, runtime settings, graph object count/order and Result Item/List access remain strict.
