This file records repository and workstation conventions that coding agents should read before changing Brepia.

Reconcile documentation against the current implementation before making changes. The live code and current architecture documents take precedence over historical implementation plans.

## Application architecture

- TanStack Router / React Start owns application and API routing.
- `src/router.tsx` creates the router from the generated `src/routeTree.gen.ts`.
- File routes live under `src/routes/`; server API routes live under `src/routes/api/`.
- Shared server-side application logic lives under `src/server/`.
- Supabase provides PostgreSQL, authentication and storage; it is not the primary HTTP application router.
- `./start.sh` is the canonical local launcher and defaults to the stable production-like runtime. Set `PCAD_ENABLE_HMR=1` only when explicit Vite HMR is wanted.

## Local Supabase lifecycle

The local Brepia Supabase stack is owned by the repository-local Supabase CLI, invoked through `npx`.

Current workflow:

- a globally installed `supabase` binary is not expected; use `npx supabase ...` from the repository;
- `./start.sh` enables the rootless Podman socket, configures the repository Podman compatibility shim, checks the local stack and runs `npx supabase start` automatically when the stack is not already running;
- explicit lifecycle commands are `npx supabase start`, `npx supabase status`, and `npx supabase stop` after configuring the same rootless Podman environment used by `start.sh`;
- database changes are schema-first: edit `supabase/schemas/`, generate a migration with `npx supabase db diff -f <migration_name>`, review it, apply it locally, then regenerate types;
- regenerate database types with `npx supabase gen types typescript --local > shared/database.ts`;
- never use `supabase db push` / `npx supabase db push` or `supabase db pull` / `npx supabase db pull` for the normal local workflow;
- never hand-edit `shared/database.ts`.

`docs/local_supabase_lifecycle.md` is the canonical local-operation reference. `scripts/inspect-local-supabase-lifecycle.sh` is a read-only troubleshooting inventory.

## Compatibility boundaries

Do not rename or remove compatibility-sensitive identifiers as part of unrelated cleanup. In particular:

- `/cadam` remains a legacy compatibility redirect while `/` is canonical;
- `CADAM Original` is an active built-in prompt/profile lineage;
- Sentry `adamcad`, `PCAD_*`, compatibility-sensitive `pcad_*`/`pcad.invalid`, existing `pcad-*` integration identifiers, and the `adam-*` design-token layer require explicit migrations before renaming.

Historical transition/checkpoint documents are not operational dependencies and should not be recreated when current documentation already describes the live system.

## Generated files

`src/routeTree.gen.ts` is generated by TanStack Router. Regenerate it through the normal Vite/TanStack toolchain; do not hand-edit it.

`shared/database.ts` is generated from the local Supabase schema; do not hand-edit it.

## Validation

After source changes, run the relevant repository gates and fix failures caused by the change:

```bash
npm test
npm run typecheck
npm run lint
npm run build
git diff --check
```

Before handoff, inspect `git status --short`, the final diff, the current branch/HEAD and its ahead/behind state against the intended base branch.
